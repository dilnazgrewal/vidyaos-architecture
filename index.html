How to read the API pills

Path A SDKBrowser talks directly to Supabase. supabase.from(...). JWT + RLS filter the data.
Path B APIBrowser calls a Vercel serverless route first. /api/*. Server uses the service-role key.
RPC DB FNA PostgreSQL function called for atomic multi-table work. supabase.rpc(...).
WS REALTIMEWebSocket subscription for live updates. supabase.channel(...).

System Overview — with API paths

The 6-layer architecture. Blue lines = Path A (direct SDK). Amber lines = Path B (via Vercel API routes). Each line is labeled with the actual call.

Every API in the system — grouped by path

supabase.auth.signInWithPassword()SDKLogin. Username → username@vidyaos.local. Returns JWT stored in HTTP-only cookie.
supabase.from('table').select/insert/upsertSDKAll everyday reads and writes — students, attendance, marks, fees, timetable, notices, homework.
supabase.rpc('fn_name')DB FNAtomic multi-table ops: record_fee_payment, get_exam_results, create_student_with_enrollment.
supabase.channel().on()REALTIMELive dashboard, and job-status updates for bulk report cards.
supabase.storage.from().upload()SDKPhoto uploads (browser). Signed URLs for reading private files.
POST /api/auth/create-userAPIAdmin creates a teacher/staff account (needs service-role key — can't run in browser).
POST /api/students/bulk-importAPIValidated Excel rows → batch insert. Server re-validates and checks duplicates.
POST /api/students/promoteAPIYear rollover — creates new enrollment rows for the next class.
POST /api/receipts/generateAPIRenders a fee-receipt PDF, uploads to Storage, returns a signed URL.
POST /api/reports/bulk-report-cardsAPIQueues a background job; a Supabase Edge Function generates the PDFs.

Backend Layer — the two API paths in detail

How a request is handled. Path A goes straight to the database; Path B goes through a Vercel function first. Both end at RLS.

Backend endpoints — full list with method + role

POST /api/auth/create-userAPICreate account. principal, clerk. Uses auth.admin.createUser() + inserts profiles/staff.
PATCH /api/auth/reset-passwordAPIReset a user's password. principal only.
POST /api/students/bulk-importAPIBatch insert students from validated JSON. principal, clerk.
POST /api/students/promoteAPICreate next-year enrollments. principal.
POST /api/receipts/generateAPIFee receipt PDF → Storage → signed URL. accountant, principal.
POST /api/reports/bulk-report-cardsAPIQueue job → Edge Function generates PDFs → ZIP. principal.
rpc('record_fee_payment')DB FNPayment + payment_items + ledger update in one transaction. accountant.
rpc('get_exam_results')DB FNTotals, grades, ranks computed in SQL. class_teacher, principal.
rpc('create_student_with_enrollment')DB FNStudent + parent + enrollment atomically. principal, clerk.

Deployment Layer — where each API physically runs

Path A code runs in the browser. Path B code runs as Vercel functions in Mumbai. Both reach Supabase in Mumbai.

Where each API runs (and which key it uses)

Path A callsSDKRun in the browser with the public anon key. Safe because RLS filters every row by the user's JWT.
Path B routesAPIRun as Vercel serverless functions in Mumbai, holding the secret service-role key that never reaches the browser.
Edge FunctionsDENORun inside Supabase for heavy async jobs (report-card PDFs, dashboard stats).
pg_cronRuns inside PostgreSQL — no API call, no server. Refreshes cache, flags defaulters/absentees.
